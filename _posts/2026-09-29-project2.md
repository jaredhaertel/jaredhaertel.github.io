This project explores convolutions and thinking about and manipulating images in terms of frequencies. Part 1 focuses on convolution and applies it to edge detection while part 2 uses low-pass and high-pass filters to sharpen images, build hybrid images, and blend images together.

# Part 1: Fun with Filters

## Part 1.1: Convolutions from Scratch

A 2D convolution slides a flipped kernel over the image and takes a weighted sum at every position. I have three implementations ranging from most naive to least, all with zero padding and "same" output size, meaning that the output has the same shape as the input by padding the input image appropriately with zeros. All three flip the kernel and then compute a correlation. 

The first version uses four loops: two over output pixels and two over kernel entries.

```python
def conv2d_v0(im, kernel):
    """
    2d convolution with "same" padding for a kernel of odd length using 4 loops
    """
    assert kernel.shape[0] % 2 == 1 and kernel.shape[1] % 2 == 1

    height, width = im.shape

    kernel = kernel[::-1, ::-1] # flip kernel and do correlation
    k_h, k_w = kernel.shape

    padded = np.pad(im, pad_width=((k_h // 2, k_h // 2), (k_w // 2, k_w // 2)))
    out = np.zeros_like(im)

    for i in range(0, height):
        for j in range(0, width):
            for h in range(0, k_h):
                for w in range(0, k_w):
                    out[i, j] += kernel[h, w] * padded[i+h, j+w]
    return out
```

The second version replaces the two inner loops with an element-wise product and sum over the window.

```python
def conv2d_v1(im, kernel):
    """
    2d convolution with "same" padding for a kernel of odd length using 2 loops
    """
    assert kernel.shape[0] % 2 == 1 and kernel.shape[1] % 2 == 1

    height, width = im.shape

    kernel = kernel[::-1, ::-1] # flip kernel and do correlation
    k_h, k_w = kernel.shape

    padded = np.pad(im, pad_width=((k_h // 2, k_h // 2), (k_w // 2, k_w // 2)))
    out = np.zeros_like(im)

    for i in range(0, height):
        for j in range(0, width):
            out[i, j] = np.sum(kernel * padded[i:i+k_h, j:j+k_w])
    return out
```

The last version uses no loops by taking advantage of `sliding_window_view`, which returns a view of every kernel-sized window of the padded image without copying any data. Using `einsum` then multiplies each window by the kernel and sums.

```python
def conv2d(im, kernel):
    """
    2d convolution with "same" padding for a kernel of odd length
    """
    assert kernel.shape[0] % 2 == 1 and kernel.shape[1] % 2 == 1

    height, width = im.shape

    kernel = kernel[::-1, ::-1] # flip kernel and do correlation
    k_h, k_w = kernel.shape

    padded = np.pad(im, pad_width=((k_h // 2, k_h // 2), (k_w // 2, k_w // 2)))

    # Generate numpy views of the same shape as kernel
    # Shape is (padded.shape[0], padded.shape[1], k_h, k_w)
    windows = sliding_window_view(padded, (k_h, k_w))

    return np.einsum('ijkl,kl->ij', windows, kernel)
```

I tested all three against `scipy.signal.convolve2d(im, kernel, mode='same')` on a grayscale picture of myself (1539 × 1154 pixels, shown below), with runtime evaluated using the 9 × 9 box filter (every entry is $1/81$).

| **Implementation** | **9 × 9 box filter runtime** | 
| :--- | ---: |
| Four loops (`conv2d_v0`) | 46.564 s |
| Two loops (`conv2d_v1`) | 3.070 s | 
| Vectorized (`conv2d`) | 0.122 s |
| `scipy.signal.convolve2d` | 0.107 s | 

All three matched scipy up to floating point error. Clearly, the more for loops used in python, the slower the code, with runtime in general growing with kernel and input image size.

**Boundaries.** Both my implementations and scipy's default pad the images with zeros. However, this creates a border where the kernel averages in black pixels, so heavily blurred images have a vignette effect which can create wonky results with derivatives (false edges!). This can be mitigated by reflecting across the borders instead such as with `scipy.ndimage.convolve(..., mode='reflect')`, which we make use of later in the code.

## Part 1.2: Finite Difference Operator

Convolving with $D_x = [1, 0, -1]$ and $D_y = [1, 0, -1]^T$ approximates the partial derivatives $\partial_x$ and $\partial_y$ if we imagine the image being a surface. $D_x$ responds to vertical edges, like the tripod legs, and $D_y$ responds to horizontal edges, like the horizon. The gradient is the vector at each point containing each directional derivative, which points in the direction of greatest increase of intensity. Taking the magnitude of the gradient hence gives an orientation-independent measure of edge strength

$$
\lVert \nabla i \rVert = \sqrt{(i * D_x)^2 + (i * D_y)^2}
$$

## Part 1.3: Derivative of Gaussian (DoG) Filter

To suppress the noise, particularly from the grass, I first blurred the image with a Gaussian of $\sigma = 3$ (a 19 × 19 kernel, from the outer product of `cv2.getGaussianKernel` with itself, with size 19 chosen so that the width and height is around $6 \sigma$) and then repeated the finite differences procedure. This suppresses high-frequency textures and noise which are otherwise present in the binarized edge image.

Compared with the finite difference alone, the grass is mostly gone as planned! Overall, the edges are thicker, as each edge is spread out by the Gaussian. For the same reason, the blur also decreases the gradient magnitude, so a lower threshold is needed. Convolution is associative, so blurring and then differentiating is the same as convolving once with a derivative of Gaussian filter:

$$
(i * G) * D_x = i * (G * D_x)
$$

There is a slight technical nuance: when computing the derivative of Gaussian filter, we must use `mode='full'` to get mathematically identical images. This makes sense if we pretend $G$ and $D_x$ are zero in all directions outside of the regions they are defined.

# Part 2: Fun with Frequencies

## Part 2.1: Image "Sharpening"

A Gaussian blur $f * g$ keeps only the low frequencies of an image $f$, so subtracting it leaves the high frequencies, which is what we call the detail image $f - f * g$. Adding the detail back with a weight $\alpha$ makes the image appear sharper. We can collapse this into a single convolution called the unsharp mask filter, where $e$ is the unit impulse (a kernel with a 1 in the center and 0 everywhere else):

$$
f + \alpha (f - f * g) = f * \big((1 + \alpha)\, e - \alpha\, g\big)
$$

The filter is a tall positive spike surrounded by a shallow negative Gaussian. It sums to 1 and so it doesn't affect the average brightness. The spike with negative mild Gaussian exaggerates differences between a pixel and its neighbors, so flat regions are relatively unaffected, while locally high contrast regions become more pronounced, creating the effect of "higher detail", with $\alpha$ controlling the strength of this effect and $\sigma$ controlling the boundary between high and low frequencies.

As $\alpha$ increases, details become more pronounced, and in the most extreme case, JPEG artifacts become plainly visible, which is usually unwanted.

The effect is very subtle and can only really be noticed by paying close attention to individual strands of fuzz on Snoopy. In the second image, individual hairs are less discernible than the original, but in the third, some of the contrast is brought back. This process can't recover the higher frequencies. Intuitively, the initial blur is equivalent to multiplying the Fourier transform by a Gaussian, which decays the higher frequencies. The unsharp mask filter then performs an additional blur to amplify the higher frequencies, but does so in a way that only amplifies the detail in the dyadic interval between the support of the single blur and the support of two blurs.

## Part 2.2: Hybrid Images

A hybrid image is the low frequencies of one image plus the high frequencies of another so that up close, the high frequencies dominate what we see and from far away (or when the image is small), only the low frequencies are visible. I aligned each pair of images on two corresponding points (usually the eyes) with the provided alignment code. Then I low-pass filtered the first image with a Gaussian, high-pass filtered the second by subtracting its own Gaussian blur from it (the impulse minus Gaussian filter), and added the two.

**Choosing the cutoffs.** A larger $\sigma_1$ removes more of the first image's detail while a smaller $\sigma_2$ keeps only the finest detail of the second. I tuned both by eye, increasing the low-pass cutoff so that the first image isn't too visible up close, and lowering the high-pass cutoff such that the second image isn't visible from far away.

# Multi-resolution Blending

## Part 2.3: Gaussian and Laplacian Stacks

Similar to Gaussian pyramids from the previous project, we know the Gaussian stack $\{g_i\}_{0 \leq i < N}$ blurs the image repeatedly except without downsampling, so every level has the full image size. Each Laplacian level $\ell_i$ is the difference between two consecutive Gaussian levels, giving a dyadic band of frequencies. The last Laplacian level is the final (blurriest) Gaussian level itself, so the whole Laplacian stack sums back to the original image exactly. In summary, we have the relations

$$
\ell_i = g_i - g_{i+1}, \qquad \ell_{N-1} = g_{N-1}, \qquad \sum_{i=0}^{N-1} \ell_i = g_0
$$

I implement the Gaussian blur as two 1D passes, one down the columns and one across the rows, since based on an Acerola video (a computer graphics youtuber), this is faster for rank 1 matrices such as the Gaussian kernel! Indeed, separating the blur this way gives the same result as the full 2D kernel, but costs $2k$ instead of $k^2$ multiplies per pixel for a $k \times k$ kernel. For the large mask blurs in the next part, this massively sped up some large blurs.

For the apple and orange I used 5 levels with $\sigma = 4$ for the images. The mask stack uses a larger $\sigma = 20$, so the seam gets wide enough to hide the transition.

## Part 2.4: Multiresolution Blending

How does the above apply to image blending? If we were just to split both images in half and combine, there would be a sharp line! We could do a smoother mask, but this doesn't respect the scales at which the details live, as we want the gradient of the mask to match this scale. Instead, we have a mask at each band-pass level matching the dyadic interval in which it lives, producing a much smoother image blend.

More specifically, we use a Laplacian stack for both images and a Gaussian stack for the mask, combining each level with its mask, and sum over each level:

$$
\text{merged image} = \sum_{i} \Big( m_i\, \ell^A_i + (1 - m_i)\, \ell^B_i \Big)
$$

### Frozen on the Pillar

Inspired by Han Solo being stuck in carbonite, I want to appear as a frozen giant on a pillar on the Benicia-Martinez Bridge from a photo I took while on Amtrak.

I scaled and positioned my photo first so the silhouette lands on the pillar in GIMP. This blend uses 10 levels, a small $\sigma = 2$ for the images and $\sigma = 20$ for the mask. Unlike the Beherit, I converted my photo to grayscale and kept its own lowest frequencies instead of replacing them with the pillar's to preserve the shading on my face and shirt. We also see the shadows from the bridge are also cast upon me which creates a neat effect.

# What I Learned
A common theme from my Fourier analysis class was to develop a dyadic way of thinking: decompose something into dyadic intervals as a way to silo different behaviors. The same rings true in image processing, where low-pass and high-pass filters select all those frequencies close or far from the center respectively, with the parameter controlling at which scale this occurs. This principle especially holds true for Laplacian stacks, which decompose the image into dyadic bands. This allows us to operate on images at a localized frequency, giving more natural results such as in image blending.
